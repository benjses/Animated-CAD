    How to use one description for multiple components

    There are three ways to use one component description in an alib-file for multiple kinds of components:
    The first, most common way is to create schematic section for qucs and one for eeschema. This way this description describes component type both plattforms. See Example 1 below.
    The second way is to add ALIAS lines.This is a line that starts with the word "ALIAS " (written in uppercase, without the apostrophes). After this buzzword, you can list up all the names this component may have - see in Example 2, below.
    The third way is to create multiple schematic sections, See in Example 3.

    The difference between the second and third way is, that when you use the ALIAS line, then the component will be written as if it would be the original, non-alias component. So the only effect of the ALIAS-line is, that the component type will also be found as this type of component.
    But when you use another schematic section within a component description, then the component will be the one described in its own schematic section. So it can have different variables, and therefor the behaviour or the look of the component may be different. An example for this is the standard resistor, in the components library called components.alib. This resistor has two eeschema-schematic-sections, where one is called pspice:R and the other one is called Device:R.
    This is necessary, because the resistor in the "pspice"-library is drawn larger in the .sch-file than the resistor in the "Device"-library. So the two resistor types have their connections at different positions, see at this screenshot from kicad eeschema.
    So here we need the third way: By creating multiple schematic sections, the component type does NOT have a default type, and the positions of the connections are calculated correctly. If we would have created an ALIAS-line in this case, then there would be a default component type, and the other component type would behave as the default type - which means it would also use the coordinates of the other type. Those components would be drawn in the same size and connections would not match.

    Having a default type can be useful in other examples, as you may find many ALIAS-lines in the library for logic-components, logic.alib:
    Here we simply can define a default type, for example the 74HC00 AND-Gate, and the we can set the derivatives, which have the same coordinates and the same spice-model to the default type. This means that the derivatives, for example components of the type 74LS00 will be drawn and will behave in a simulation exactly the same as the default type.
    Also when you use an ALIAS-line, you can place many derivative components in that line, and you can use as many ALIAS-lines as you like. This way is the shortest way to create multiple components.
