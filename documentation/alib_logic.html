    Logic statements

    The .alib library format is called "advanced library", because unlike the usual libraries in .lib-format (.lib documentation in english|german),the alib format supports logic statements and variable declarations
    But before learning these details of alib-files in this document below, you might want to read the introduction about how to create alib-files

    General structure of logic statements in .alib

    The central four logic buzzwords are: IF THEN ELSE ENDIF
    These buzzwords must be written in uppercase letters. The ELSE is optional.

    The IF-statement

    For the if-statement between IF and THEN you can use a comparation word from the ones listed below.

    If you do NOT use a comparation word, then this if-statement will be false when the text in the statement is "null" or when that text is blank (for example if that text is "", because apostrophes are ignored here) or when that text starts with a bracket [ and ends with a bracket ] (this is useful to check if that variable is defined or not). Otherwise that statement is true.

    If you do use a comparation word in the if-statement, then this statement is decided by your choosen comparation word. You may choose one of these:

    Type comparisons:
  • IS_NUMBER: true when the other word between IF and THEN is a number, false otherwise.
    •
    Text comparisons:
  • EQUAL_TO: true when both texts are same, false otherwise.
  • STARTS_WITH: true when the first text starts with the second text, false otherwise
  • ENDS_WITH: true when the first text ends with the second text, false otherwise
  • CONTAINS: true when the first text contains the second text, false otherwise
  • MATCHES: true when the first text matches the second text as a regular expression, false otherwise. The regular expression need slashes doubled, as regular expressions in java language use double slashes. It is advised to test this comparison type extra intensively.
    •
    Numeric comparisons: changes both texts into float values. If that text before or after the comparation word is not a value that can be parsed into float, then makes warning dialog and returns false
  • EQUAL_OR_HIGHER_THAN:true when the first value is equal or higher than the second value, false otherwise
  • EQUAL_OR_LOWER_THAN:true when the first value is equal or lower than the second value, false otherwise
  • HIGHER_THAN:true when the first value is strictly higher than the second value, false otherwise
  • LOWER_THAN:true when the first value is strictly lower than the second value, false otherwise
  • LOWER_OR_HIGHER_THAN:true when the first value is strictly higher or strictly lower than the second value
    •  Existence of variable:
  • [variable]:true when the variable [variable] exists and has a value which is not blank, and not between the brackets "[" and "]" and is not "null".
    •
    Attention comparisons ignore leading whitespaces, trailing whitespaces, brackets and apostrophes:
    Examples: let's assume a resistor, which has the pins [pin1] and [pin2], and has a variable [smbl], which has the value "US", as the example below:
    IF[smbl]EQUAL_TO international is false.
    IF[smbl]EQUAL_TO US is true.
    IF[smbl] is true, because "US" is not empty and not null and not in brackets
    IF[non_existant_variable]is false.
    IF[pin1] is true in spice section, but false in drawing section, because [pin1] is being defined in drawing section.
    IF[pin999] is false, because [pin999] does not exist.

    The THEN-statement

    This is the part between THEN and ELSE or between THEN and ENDIF. It is executed when the if-statement is true.

    The ELSE-statement

    This statement can be omitted. If it is not omitted, then it is the part between ELSE and ENDIF. It is executed when the if-statement is false.

    Example of logic statement in drawing section

    The following example draws a resistor, similar to Example 1 in the introduction about how to create alib-files, but here we use the variable [smbl] which can take the values "US" or "european" to decide whether we draw the in the american symbol according to ANSY Y32 (like this:-/\/\/\/\-) or the european/international norm according to IEC 60617 (like this:-[:::::]-, the different styles of how resistors are drawn is also described on in this explainating website.
    This component can also be found in the standard components library

      <qucs_symbol>
       IF [smbl] EQUAL_TO "US" THEN
         // Drawing of resistor in US-style:
        <Line -18 0 3 -9 #000080 2 1>
        <Line -15 -9 6 18 #000080 2 1>
        <Line -9 9 6 -18 #000080 2 1>
        <Line -3 -9 6 18 #000080 2 1>
        <Line 3 9 6 -18 #000080 2 1>
        <Line 9 -9 6 18 #000080 2 1>
        <Line 15 9 3 -9 #000080 2 1>
       ELSE
         // Drawing of resistor in international style:
        <Rectangle -18 -9 36 18 #000080 2 1 #000080 1 0>
       ENDIF
         // Pins and connection lines to pins are independent of drawing style:
       <.PortSym -30 0 [pin1] 0>
       <.PortSym 30 0 [pin2] 0>
       <Line -30 0 12 0 #000080 2 1>
       <Line 30 0 -12 0 #000080 2 1>
      </qucs_symbol>
    By the way: The variable [smbl] is only declared in the <qucs_sch>, but not in the <eeschema_sch> section. So if we would use this drawing not in <qucs_symbol> but in <eeschema_symbol> then it would draw the international symbol, because the text "[smbl]" would not be replaced by its value. And "[smbl]" is not equal to "US" so the if-statement is false, so the else path is executed.
    (Also the component would be drawn very small and the connections' coordinates not match the circuit around that resistor, because Eeschema uses different coordinates than Q.U.C.S. This would lead to an error message, stating that the resistor is not connected.)

    Example of logic statement in spice section

    In the spice section you can use logic statements as well. The following example is of a MOSFET, where the variable [type] can take the values "nfet" or "pfet" and decides whether that component is a N-channel MOSFET or a P-channel-MOSFET. This component can also be found in the standard components library
    <Spice>
    .model M_MDL_[name] IF [type] EQUAL_TO "nfet" THEN nmos ENDIF IF [type] EQUAL_TO "pfet" THEN pmos ENDIF level=6 // Transistor model M_MDL_[name] created based on value of [type]
    M_[name] [d] [g] [s] [b] M_MDL_[name] l=[L] w=[W] M_MDL_[name] // Component sets further parameters and calls the model.
    </Spice>
    In this example, we see that the Ngspice model type is chosen to be either "nmos" or "pmos" depending on the variable [type]. These model types can be found in chapter 11.2 "MOSFET models" in the Ngspice user manual
